2026-11-15. **Preproduction only. Not a signed feed, target policy, or approved publication.** This is a separate client review slice, not an amendment of Pi Draft #451 or historical legacy Directory sequence 48. No source, revocation, ledger, bootstrap, key or publisher file is changed.

## Independently observed source boundaries

The released client-capabilities contract from UAP agentplugins-v0.1.108, frozen at 8c3cfa28e332c533b0cc0845739c0275730a4285, contains 17 clients. It identifies Hermes User Skills plus stdio/Streamable HTTP MCP, **Hermes Project Skills but NO Project MCP**. Antigravity User/Project reports native Skills and stdio/Streamable HTTP MCP; SSE/apps remain unsupported. A broad client capability is **not** evidence that any pinned package's actual transports, client storage, dependencies, authentication or lifecycle has been verified. The real native Antigravity healthy saved repair failure observed with released CLI 0.1.108 in [UAP #909](https://github.com/777genius/universal-agent-plugins/pull/909) must be resolved and *the corrected CLI publicly released* before acceptance. Prepared/native implementation details must be confirmed from that release, not inferred from client metadata.

The Registry main source at edab3b0065ccf259579f67888a2fffe2f2b54e34 contains 36 active distributions with 36 active policies: **35 require MCP** (33 MCP-only, 2 MCP+Skills), **1 requires Skills** (777genius/marketing-kit). A 37th active policy belongs to a **suspended distribution** and is excluded. No Hermes/Antigravity target appears in the signed legacy source. All **36/36 complete Hermes Project packages are structurally incompatible** with the frozen native Project MCP boundary: 35 roots require MCP directly; the Skills-only Marketing Kit root requires *three mandatory MCP child distributions*: Notion 0.1.0, HubSpot CRM 0.1.0, and Playwright Bridge 0.0.80. The first surfaced HubSpot refusal is not the whole dependency closure. These source-declaration checks are negative compatibility evidence only, not positive reviewed grants or a substitute for transitive source/materialization proof. Hermes User and both Antigravity scopes require separate per-source review. No count here constitutes successful installed or signed policies.

The read-only audit script produces a *non-authoritative, unsigned* report from exact Git commit blobs, the SHA-256 pinned 17-client contract and every active policy/source digest. For registry-local exact-source TOML, the audit also follows pinned mandatory dependency release identities and denies incompatible child capabilities. The report marks compatible-looking rows review_required, not PASS; unsupported Hermes Project MCP rows native_incompatible; suspended rows excluded. It **cannot** create targets, signatures, saved receipts, publishable JSON, grants or keys. CI on three runners checks that exact static source audit only, **not three-OS saved E2E**. No synthetic evidence is accepted.

## Required separate review / test gates

- Per active distribution/release, independently inspect exact immutable package source revision, path, manifest/tree digests, every required transport and auth mode, plus all *transitive* dependency constraints and signed child eligibility. In particular, do not convert direct-source HubSpot compatibility into signed Marketing Kit dependency authority.
- For Hermes, qualify User Skills/MCP and Project Skills separately. Explicitly reject Project MCP packages and any package whose required component/transport is unavailable. For Antigravity, test native vs prepared action semantics and verify that healthy repair genuinely succeeds with an immutable publicly released fixed CLI. Preserve owner/foreign-file state.
- On Ubuntu/macOS/Windows, for **each scope and structurally eligible immutable release**, produce native real managed saved add, locked dependency sync, info, update, repair and remove receipts, idempotence, isolation, no unauthorised host writes, and negative unsupported component/auth/transport cases. Exact source identities and release binary/build provenance must agree across all reports. Keep refused/suspended cases failures/exclusions, never PASS.
- Pi #451 is a *separate* evidence scope. Even a future real signed Pi 72/72 would **not** satisfy Hermes/Antigravity. Combined all-client acceptance must enumerate each distribution × client × scope × OS with explicit expected applicability; the 35 Hermes Project MCP cases are unsupported, not skipped successful installs.
- [Owner security gate #479](https://github.com/777genius/universal-agent-plugins-registry/issues/479) must first approve independently hosted HTTPS modern schema-1 origin/feed ID, a distinct public Ed25519 key with protected signer environment/KMS, authorized reviewers and immutable sequenced ledger with CAS, revocation, rollback and expiry rules. No test key or old key may be reused.
- Only then wire the approved *public* trust root into a genuinely released CLI, verify automatic separate short-name routing, saved updates/repairs/lock restoration, negative wrong-key/replay/revocation/cross-feed tests, and protected production publisher provenance and CDN/site byte equality. Legacy CLI 0.1.89 and sequence 48 remain byte-identical and valid.

The source audit is deliberately the **first gate only**. It makes no claims about completed native three-OS saved flows, reviewed transport/auth, signed grants or production readiness.
